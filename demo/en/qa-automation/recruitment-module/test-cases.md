# Test Cases: Recruitment Module

## Summary

This set covers vacancy management, candidate management, public apply flow, pipeline transitions, access control, and the documented Hiring Manager-related defect.

Assumptions and open questions:

- Vacancy Name uniqueness case sensitivity is not explicitly defined.
- The exact wording for Number of Positions errors is documented for the observed invalid categories, but the field may still render the same message for multiple invalid inputs.
- The default toggle state for Active and Publish in RSS Feed and Web Page is not asserted here unless the requirements explicitly show the outcome.
- The known HTTP 500 on missing Hiring Manager is treated as a defect reproduction case, not an expected product path.

## Automation Notes

- `REC_RECRUITMENT_TC_043` is a defect reproduction case and should not be used as a normal regression assertion.
- Cases that require existing candidate states such as Application Initiated, Interview Scheduled, Interview Passed, Job Offered, Offer Declined, and Interview Failed depend on setup that moves a new candidate through the real workflow before the main assertion.
- Cases that depend on authenticated roles require separate Admin and ESS storage states or login setup.
