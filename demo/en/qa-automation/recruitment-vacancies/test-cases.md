# Test Cases: Recruitment > Vacancies

Summary:
- This set covers the core vacancy list, filters, create flow, template import, workflow, application form, smart screening, job posting, public application impact, permission behavior, and state transitions.
- The cases are written for manual review first and later Playwright automation.
- Live UI confirmation is still needed for some field types and status values.

Assumptions:
- The environment supports authenticated access to OrangeHRM Recruitment.
- Seeded master data exists for Job Title, Location, Subunit, workflow, and vacancy templates.
- Test users can be created or assigned as needed for permission coverage.

Open questions:
- AMB-01: Which fields are strictly required in the current Add Vacancy form?
- AMB-02: What are the exact control types and default values for vacancy filters?
- AMB-03: Which values appear in the Vacancy Status filter?
- AMB-04: Are the documented action labels still current in the live UI?
- AMB-05: Does template import overwrite or merge existing vacancy input?
- AMB-06: Is Hiring Manager mandatory, and can multiple hiring managers be assigned?
- AMB-07: What validation messages appear for missing or invalid inputs?
- AMB-08: Can the live authenticated demo UI be verified directly before automation begins?

## Automation Notes
- TC_008 is automation-sensitive until the live UI confirms which fields are required and which validation messages are shown.
- TC_009 depends on a real vacancy template and on the exact import behavior in the live UI.
- TC_010, TC_011, and TC_012 depend on seeded workflow and question data; automation should use created test data, not shared demo records.
- TC_013 and TC_014 depend on the current Job Posting actions being confirmed in the live authenticated UI.
- TC_015 and TC_016 require a published public vacancy page and are blocked if the environment does not expose public job posting.
- TC_019 depends on an available restricted test account or a role that clearly lacks vacancy creation permission.
- TC_020 is partially blocked until the available row actions are confirmed in the live UI.
